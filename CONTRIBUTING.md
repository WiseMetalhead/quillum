# Участие в разработке

Спасибо за интерес к Quillum. Ошибки и предложения можно создавать через GitHub Issues, изменения —
через pull request.

## Основные правила

- Не добавляйте секреты, реальные пользовательские данные и приватные адреса инфраструктуры.
- Сохраняйте изменения в рамках одной задачи и не переписывайте несвязанный код.
- Любая новая строка интерфейса должна одновременно появляться в русском и английском каталогах.
- Изменения схемы Django всегда сопровождаются миграцией.
- Пользовательские данные Quillum остаются plaintext на уровне приложения; не добавляйте скрытый
  слой прикладного шифрования.
- Отправляя вклад, вы соглашаетесь распространять его по AGPL-3.0-or-later. CLA и DCO не требуются.

## Локальная среда

Для разработки нужны Node.js 24, Python 3.12, uv, PostgreSQL и Redis. Подробные команды находятся в
[руководстве разработчика](docs/public/development.md).

Перед pull request выполните frontend, collaboration и backend-проверки. Полный backend suite может
занимать продолжительное время.

## Pull request

Опишите цель, пользовательский эффект, миграции/конфигурацию и выполненные проверки. Для визуальных
изменений приложите снимки desktop и mobile состояний без реальных пользовательских данных.
